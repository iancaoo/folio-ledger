# 使用与开发参考

本文保留详细业务约定、测试脚本和打包说明。首次安装请从仓库 [README](../README.md) 开始；文中命令均在仓库根目录执行。历史验证不代表当前版本重新执行了全部测试。旧浏览器脚本部分仍依赖旧导航，适配状态见 [开发进度](开发进度.md)。

## 已打通的开发流程

1. 基金页面新建基金；演示按钮可填入一份明确标记的模拟资料及两份额。
2. 客户页面新建两个投资主体，使用相同客户编号。
3. 为一个主体的一种份额申购 100，再赎回 30。
4. 保存单位净值 1.25。持仓显示 70 份，市值 87.50。
5. 尝试撤销原 100 份申购，会因历史负份额被拒绝。
6. 导入页面选择净值、收益或基准数值。选择整份文件使用一个对象，或每行通过 ISIN／基准 ID 识别对象；下载模板及参考，确认列映射，修正错误后预览并提交选中集合。
7. 选择“申赎交易”，下载含主体及份额参考的模板。每行填写主体 ID 和 ISIN，费率明确选择百分数或比例值。交易 ID 留空表示新增；修改须填写已有交易 ID，并完整填写该行业务字段，选填项为空会清空旧值。预览展示原值、转换值及旧值，疑似重复交易需要逐行确认。
8. 选择“客户与投资主体”“基金与份额（可含成分）”或“自营成分清单”，下载相应模板。基金再选择三方或自营类型；模板附带基金、份额、主体、清单、负责人和候选项参考。

9. 在基金、主体、申赎、净值／收益、基准定义或基准数值表单中选择“保存草稿并关闭”。从“个人草稿”恢复后继续填写，正式保存成功后自动移除草稿。

交易文件按最终选中集合的每日合计校验。同日申购 100、赎回 30，无论文件行顺序如何，持仓均为 70。预览后其他人录入交易、撤销记录或修改关联资料，提交会要求重新预览；任何行写入失败均不保留部分交易。已完成批次刷新或重试不会追加交易。

时序导入约定：净值／收益按份额加日期识别，基准数值按基准 ID 加日期识别。同文件重复键须明确修正或取消选择；不同对象可使用同一日期。收益须选择百分数或比例值口径，并可映射估算标记。估算标记留空或未映射时保存为未知，覆盖正式值时显示警告；不会默默沿用旧的正式标记。核对窗口同时展示原值、修正输入、精确转换值和旧值。内容不变时保留记录修订及原来源；真正覆盖才更新来源。关联资料、同日目标或目标记录身份变化都要求重新预览。

查询约定：业务列表每页最多 200 条，可持续翻页；每页内容、关联名称和全库计数由后端查询。搜索按文字本身匹配，不把 `%` 和 `_` 当作通配符。关联选择可搜索名称、ISIN 或客户编号；同名对象同时显示业务标识。时序单条覆盖先按对象加日期查询旧值，不依赖当前页是否已加载该记录。

导出约定：在“数据导出”中选择业务表及对象、日期或状态范围。18 个当前业务表和只读持仓均可下载；默认包括已删除、停用及撤销记录。读取和计算使用同一数据库快照，金额、份额、比例及日期保留为 Excel 文本。每份最多 10,000 行、10 MB，超出时生成含行数和 SHA-256 清单的 ZIP，不受业务列表分页限制。字段说明标出单位、稳定 ID、系统字段和只读计算项；文档只导出元数据，原文件仍从文档页面受控下载。

交换文件中的 `\N` 表示空值，空字符串为空单元格，原文本开头的反斜杠增加一个反斜杠；保留 `Finance交换信息` 工作表。18 个业务表均可在导入中心选择“业务交换文件（自动识别）”，固定列映射及比例口径。只修改已有记录，保留 ID 和固定关联；新增记录仍用普通录入模板。时序记录 ID 必须对应原对象及日期；已撤销交易只能核对，修改交易仍校验整批最终持仓。持仓是只读计算结果，不能导入。

主数据交换只修改选中行，未选中及文件外记录保留。基金资料、份额、条款或成分按基金汇总，明确保存一次增加一个资料版本；重试不重复保存。成分交换先展示完整清单差异，未列出的明细不会被删除，这与普通成分模板的完整清单替换不同。客户编号改名需确认受影响的主体数量；协议和产品选项修改保留原关联 ID。主体、基准及文档分类不变时只核对，文档原文件名、大小及文件绑定不可通过交换修改。归档资料可原样核对，业务修改须先恢复。预览后的关联变化会使提交失效，任何一行保存失败均整批回滚。

只读状态、计算值、来源和修订号不由交换文件覆盖；这是业务数据交换，不是数据库恢复。超过 Excel 单元格文本上限或含不支持控制字符时明确失败，不截断字段。

关联明细保存约定：主体协议和产品中仍保留的选项沿用原 ID；调整选项顺序不重建记录。成分清单内仍保留的同一份额也沿用原明细 ID，未变项保留时间和修订号，修改项递增自身修订。删除后重新添加属于新关联。基金明确保存仍增加一个完整资料版本。

草稿约定：仅本人可读写，不进入正式业务表。允许缺必填项和待核对的原文本；单份最多 1 MB、单个明细列表最多 2000 行。页面刷新前需主动保存，关闭已修改表单时可选择继续填写、保存草稿或放弃本次修改。放弃本次修改不删除之前保存的草稿；删除草稿需在个人草稿列表明确操作。草稿和原业务记录分别校验修订号，冲突时保留输入；正式保存与草稿移除在同一事务内完成，失败不移除草稿。草稿保留至本人删除或正式提交，不适用上传文件的 7 天清理规则。

主数据导入约定：

- 空白保留已有值；`#清空` 明确清空选填项；要保存文本本身 `#清空`，填写 `##清空`。新对象的必填字段仍须完整填写。该约定适用于主体、基金及成分导入；交易按完整行输入处理。
- 主体 ID 留空为新增，已有 ID 为修改。客户编号只用于分组。多选字段在一个单元格内每行写一个选项，不能把 `n/a` 与其他协议同时选择。
- 一个基金可以有多行。已有基金用基金 ID，或由已有份额 ID／ISIN 定位；新基金用本文件内唯一的分组键。公共字段只需填写一次，重复填写必须一致。每个份额单独一行，按基金统一保存，明确保存相同内容也增加一个资料版本。
- 自营模板可同时放入“份额”和“成分”行。成分 ISIN 关联已经建立的三方份额。同基金同日期是一组完整清单；无日期的新清单使用分组键，修改无日期的已有清单使用清单 ID。替换前显示新增、修改及移除项，必须明确确认；取消选择一行会重新要求核对。要清空整组，使用“清空成分”行并指定已有清单。
- 预览保留原值、修正值和转换值，CDD 截止日期只读计算。存在未校验项时不会显示为已通过；参考资料或目标修订变化会要求重新预览。任何后半批错误均回滚整批业务记录及基金版本。

数据质量工作台：

- 按检查业务日查询持仓无净值、收益估算标记缺失、枚举待确认、导入错误、成分缺数及未来日期记录。支持按对象、基金、主体和问题类型筛选，问题列表分页显示；统计与当前页来自同一读取视图。
- 缺净值带入份额和日期；收益带入原百分数及估算标记；成分打开原基金聚合并定位字段；枚举问题打开来源字段的候选配置。只有对应角色可修正，系统不自动确认业务口径。
- 导入问题只列本人的选中错误行和解析失败批次。打开后跳到对应页并高亮原文件行；已提交和已取消批次可只读查看原值和当时的修正值。已入库记录也可通过来源坐标定位原行；其他人的原文件名称和内容不会由工作台开放。
- 未来日期检查覆盖交易确认日期、净值、收益、基准数值及成分估值日期，仅提示核对。时序表按对象加日期保存：新日期另存一条，不会隐式搬移原记录；错误记录可明确删除后重新录入。基准日期值可单独删除，基准定义保留。
- 工作台显示本人最近 5 个导入批次。修正后重新检查，问题会按实际数据消失；不维护另一份业务状态。旧净值不设未经确认的逾期天数。

开发环境的候选项仍是演示配置。关闭 `FINANCE_DEMO_MODE` 后，尚未确认的候选集会阻止正式写入。不要把当前演示配置当作业务决定。

管理员可在“字段候选配置”维护选项和确认状态。三方、自营、交易币种分别维护；原表缺失项不自动补造。平台管理员分配 `finance_editor`（录入）、`finance_reader`（只读）、`finance_configurator`（仅候选配置）角色；`finance_product` 作为产品组成员标记，正式模式下追踪负责人从此组选择。业务角色没有页面设计、改表或插件管理权限。

文件诊断与解析约定：

- 首表公式必须有可核验缓存。支持本表数值引用、加减乘、可精确核验的除法、括号、百分号及 `SUM`；除法若不能在 40 位小数内精确表示，或含外部引用、数组、其他函数、错误单元格，要求重新计算后转为数值文件。比较缓存采用 15 位有效数字，保留文件中的缓存数值，不用系统重算值替代原数据。
- XLS 数字单元格超过 15 位可靠范围时拒绝解析，并定位单元格。请从原始精确资料改填文本；改变显示格式不能恢复先前已丢失的位数。XLSX 保留文件中的原数值字面量；两种格式均按文件日期系统处理。
- 解析错误不留下部分导入行。原件可下载，修正内容后新建批次；“重试解析”用于原文件未变的临时故障。解析规则升级前的未完成批次也须新建批次重新核对，历史原件及纠错记录保留，已提交结果不重复执行。
- 文件解析在独立线程执行，期间可取消；单次 60 秒超时、512 MB V8 堆上限，持久认领租期 120 秒。应用每 30 秒恢复待办任务，进程异常后可接管过期认领。待上传和已有原件的任务分别处理，失败任务按最近尝试时间轮转。
- `FINANCE_IMPORT_ORPHAN_RETENTION_HOURS` 默认 168 小时、至少 1 小时，只清理符合系统命名的过期孤立原件和 `.part` 残片。已关联批次的原件，包括取消或已提交批次，继续保留。

`tests/browser-file-parser.ts` 验证公式缓存诊断、合法缓存导入、XLS 精度错误及改为精确文本后的保存。线程退出、解析期间取消、过期接管、恢复公平性和清理边界由数据库测试验证。证据见 [文件解析与恢复验证](verification/M4文件解析恢复验证.json)。

## 当前边界

现在已有基金及主体新建修改、基金／主体删除恢复、份额停用恢复、历史资料查看、基准及数值录入、申赎新建、修改、重复确认与撤销、净值／收益录入删除、持仓查询、文件导入纠错、交易及主数据批量新增修改、完整成分导入、业务表导出页面、全部 18 个业务表的交换再导入，以及角色和候选配置。文档支持上传、受控下载、物理删除、任务恢复和取消；单文件最多 10 MB，未完成上传默认保留 7 天。自营成分清单与基金资料一并保存，权重明确缺数和跨币种原因；导入原件、本人批次与解析状态可以恢复，未提交批次可以取消。净值、收益及基准数值支持单对象或多对象导入。主要业务列表已提供服务端分页和筛选，关联对象及负责人使用远程搜索与加载更多。个人草稿已支持保存、恢复和删除；数据质量工作台及来源定位已完成技术验证。公式缓存与 XLS 数字精度诊断、后台解析、任务接管及孤立原件清理已完成技术验证。规定规模性能、隔离备份恢复及 A01—A42 技术验收已通过。

第一阶段完成状态为“本地技术交付完成，待业务确认”。正式部署和真实数据试用须完成参与清单，不能直接使用当前演示选项。报告和 Slides 属于第二阶段。

文件暂存保留时间可通过 `FINANCE_STAGED_FILE_RETENTION_HOURS` 调整（默认 168 小时，至少 1 小时）。`REQUEST_BODY_LIMIT=16mb` 用于容纳 10 MB 文件的 Base64；正式代理也需允许相应请求体。此暂存清理只处理尚未关联成功的上传，不删除已有文档。
